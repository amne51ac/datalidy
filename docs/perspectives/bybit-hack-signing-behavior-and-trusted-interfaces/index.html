The Bybit Theft and the Human Limits of Trusting What a Screen Shows

The largest cryptocurrency theft on record did not require signers to ignore warnings. It exploited the reasonable habit of trusting a familiar interface, which makes it a lesson in designing verification that holds up under routine.

Event: February 2025 · Organizations: Bybit, Safe{Wallet}, FBI
This analysis examines the event as it unfolded, based on the reporting cited below. Later developments may not be reflected.

Key takeaways

  • The FBI attributed the February 21, 2025 theft of about 1.5 billion dollars from Bybit to North Korean actors it calls TraderTraitor.
  • Safe said a compromised developer machine led to a disguised malicious transaction being proposed for signing.
  • Multi-signer approval protects only when each signer independently verifies what is being signed, not what an interface displays.
  • Supply chain risk is shared: an organization's controls depend on the security habits of every vendor in the signing path.

What happened

On February 21, 2025, attackers stole roughly 1.5 billion dollars in ether from Bybit, a Dubai-based cryptocurrency exchange. In a public service announcement on February 26, the FBI attributed the theft to North Korean actors it tracks as TraderTraitor and urged exchanges, bridges and analytics firms to block transactions linked to addresses used to launder the funds. Bybit's chief executive said the transaction had been masked, according to Benzinga: all the signers saw an interface showing the correct address, and the URL was from Safe.

Investigations pointed to the wallet software rather than to Bybit's own systems. The Hacker News reported that Safe{Wallet}, whose multisignature interface Bybit used, said the attack came through a compromised machine belonging to one of its developers, which led to a disguised malicious transaction being proposed. Forensic firm Verichains found that a JavaScript file on Safe's web application had been replaced with malicious code two days earlier, designed to activate on Bybit's next transaction. How the developer's machine was breached was not clear, the outlet reported.

The human dimension

Multisignature approval is designed so that no single person can move funds. Its strength depends on each signer verifying independently. In practice, signers often rely on the same interface, so a single deception presented to all of them can defeat the control. When every signer sees a convincing, familiar display, approving it is not a moral failing. It is the predictable result of a routine task that usually goes right, performed through a screen that had always been trustworthy.

Human factors research has long shown that people habituate to repeated confirmations, especially when the interface looks familiar and the stakes feel abstract. Security that depends on vigilance during a routine step is fragile by design. The more useful question is how to make independent verification easy, distinct and unavoidable, so that the safe behavior is also the simplest one.

The signals that mattered

Before a theft of this kind, the leading indicators are behavioral and procedural rather than technical alarms. They describe how verification actually happens, not how policy says it should.

These indicators share a theme: they reveal where a control has quietly become a ritual. When approvals take seconds, follow the same path and rarely encounter surprises, the organization has optimized for convenience, and that is precisely where a patient attacker will look for an opening.

  • Share of signers who verify transaction data on an independent device
  • Time spent per approval, which falls as signing becomes routine
  • Number of signers relying on the same interface and network path
  • Vendor access controls for code that sits inside the signing workflow
  • Frequency of rehearsed drills for unusual or high-value transactions

Lessons for leaders and investors

Controls should be evaluated by how people use them on an ordinary Tuesday, not by their design on paper. Organizations holding significant assets can separate the channels through which signers review transactions, require readable confirmation of the actual instructions, and test approvals with surprise exercises. Investors conducting diligence on exchanges, custodians and fintech firms can ask how verification behavior is measured and how third-party code in critical paths is governed.

The lesson extends to any organization where a small number of people approve high-value actions, from wire transfers to code releases. Controls that look strong on an organization chart can be defeated by a single shared point of trust, so the design of the approval experience deserves the same scrutiny as the design of the approval policy.

  • Design signing so that independent verification is the default, not an extra step.
  • Treat vendor code in approval workflows as part of your own attack surface.
  • Measure verification behavior directly through audits and simulated exercises.
  • Include supply chain and insider risk questions in diligence for financial platforms.

The public-good dimension

The FBI's request for industry help in blocking laundered funds is a reminder that security failures do not stay private. Stolen assets can finance harmful activity, and large thefts erode trust in financial technology that many ordinary users depend on. Clear, behavior-centered security practices protect individual customers and the broader system, and openly shared forensic findings help other organizations close similar gaps.
